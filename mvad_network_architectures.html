1. Architecture Overview

V1 MultivoiceVAD_CNN

A 2D CNN that treats each mel-spectrogram context window (15 frames × 40 mel bands) as a small single-channel image. Classifies each frame independently using its local context.

  • Input: mel patch (15 × 40) per frame
  • 5 Conv2d layers + 2 FC layers
  • Context: 150 ms (7 past + 1 current + 7 future)
  • Lookahead: 70 ms
  • Frame-by-frame processing (no temporal sharing)

V2 MVAD_V2 (DS-Conv1D)

A 1D depthwise-separable CNN operating on mel features along the time axis. Processes entire sequences at once, sharing temporal computation across frames.

  • Input: mel sequence (T × 40) — whole file or chunk
  • 1 input projection + 5 DS-Conv blocks + 1 output head
  • Context: 710 ms (35 past + 1 current + 35 future)
  • Lookahead: 350 ms (within 1 s budget)
  • Sequence-to-sequence (streaming-friendly)
Key design change: V2 replaces expensive 2D convolutions on per-frame mel patches with lightweight depthwise-separable 1D convolutions along the time axis. This achieves a ~600× reduction in MMAC/s while expanding the temporal receptive field from 150 ms to 710 ms, enabling better detection of overlapping speech.

Depthwise-Separable factorization: Each DS block decomposes a standard Conv1d into a depthwise conv (per-channel temporal filtering, k=15) followed by a pointwise conv (cross-channel mixing, k=1). For C=64 and K=15, this reduces MACs from 64×64×15 = 61,440 to 64×15 + 64×64 = 5,056 per frame — a 12.2× saving per block.
Streaming design: Center-aligned padding (pad = K//2 = 7 on each side) means each layer requires 7 future frames (70 ms). With 5 DS blocks stacked, the total lookahead is 5 × 7 = 35 frames = 350 ms, well within the 1 s latency budget. In streaming mode, buffer 35 frames before producing output.

6. Design Rationale

Why Depthwise-Separable 1D Convolutions?

Standard 2D convolutions (V1) treat the mel spectrogram as an image and mix across both frequency and time dimensions simultaneously. While powerful, this is computationally expensive: a Conv2d(Cin, Cout, k×k) costs Cin×Cout×k2×H×W MACs.

V2 separates the problem into two steps:

  1. Frequency mixing via pointwise Conv1d (k=1): maps 40 mel bands to 64 features. This is analogous to learned frequency weighting.
  2. Temporal modelling via depthwise Conv1d (k=15): each channel is filtered independently along time, capturing local temporal dynamics.

This factorization reduces per-layer MACs by ~12× while preserving the ability to model both spectral and temporal patterns. The 5 stacked blocks provide a 710 ms receptive field, far exceeding V1’s 150 ms context.

Latency vs Accuracy Trade-off

The 1 s latency budget allows up to 100 frames of lookahead at 100 Hz. V2 uses 35 frames (350 ms) — a deliberate choice balancing:

  • More temporal context for overlap detection (the hardest class)
  • Margin for future expansion (e.g., adding 1–2 more blocks within budget)
  • Practical streaming (350 ms buffer is acceptable for most applications)
